# SF-1 — Implementation Report

> Task: [SF-1](https://bendak.youtrack.cloud/issue/SF-1) — Initialize SkillFlow project
> Plan: [plan.md](plan.md) · Specs: SF-A-2, SF-A-3, SF-A-5, SF-A-6

## What was implemented

A locally installable `skillflow` Python package with a working executable
entry point, a running pytest suite, and the `.skillflow/` storage convention
expressed as constants. No lifecycle behaviour — exactly the scope of SF-1.

- `src` layout package `skillflow`, built with **hatchling**, environment and
  lockfile managed by **uv**. `uv sync` on a fresh checkout produces a working
  dev environment with no manual steps.
- **Zero runtime dependencies.** Dev-only: `pytest`, `ruff`.
- **argparse CLI** exposing only `--version` and `--help`. Bare `skillflow`
  prints help and exits `0`. The four lifecycle commands are not stubbed.
- `python -m skillflow` delegates to the same `cli.main`.
- Version single-sourced from `src/skillflow/__init__.py` via hatchling's
  `dynamic = ["version"]` — `pyproject.toml` and `__version__` cannot drift.
- `workspace.py` holds four naming constants and a docstring documenting the
  `.skillflow/` layout. No filesystem I/O, no root detection (SF-3's scope).
- README gains a **Development** section and a **Storage layout** note.

## Important implementation decisions

- **`main()` returns `int`** rather than calling `sys.exit`, keeping it directly
  testable. `__main__.py` and the console script both propagate the code.
- **No `add_subparsers()`** — an empty subparser container would freeze a
  command contract before SF-A-5's preconditions/error types exist (SF-19).
- **`workspace.py` is constants only** — repository-root detection, workspace
  creation, idempotent setup, and SQLite init are SF-3's explicit deliverables.
- **`DB_FILE_NAME = "skillflow.db"`** — SF-A-2 leaves the exact filename an
  implementation detail; this is the concrete choice SF-3 will consume.
- **`.skillflow/` is gitignored** in this repo only (SkillFlow dogfooding
  itself). SF-A-2 §3 leaves the commit/ignore question open for target repos, so
  no `.gitignore` template is shipped and no global rule is claimed.
- **`.python-version` = 3.11** while the machine runs 3.14 — deliberate, per
  plan §13. uv auto-downloaded CPython 3.11.16 (one-off 25.9 MiB).

## Deviations from the plan

- The plan's `cli.py` sketch put the parser `description` on a single line. Under
  the configured ruff line length (88) that line was 92 chars (`E501`), so the
  string is wrapped in parentheses across two lines. Behaviour is identical;
  no interface change.
- `__main__.py` uses `if __name__ == "__main__": raise SystemExit(main())`. Plan
  §4 wrote `sys.exit(main())` and §5 step 4 wrote `raise SystemExit(main())` —
  internally inconsistent, and neither addressed the import guard. The guarded
  form (review finding 1) is the correct resolution; `python -m skillflow`
  behaviour is unchanged and covered by the subprocess tests.

Nothing else diverged. `plan.md` still accurately reflects the implementation.

## Review follow-up

The independent Review Run returned `APPROVED` with four `MINOR` and two `NIT`
findings. All six were applied in this Run:

| # | Finding | Fix |
| --- | --- | --- |
| 1 | `__main__.py` ran the CLI on *import* (no `__name__` guard) | added `if __name__ == "__main__":` guard |
| 2 | entry-point test never exercised `main()` return-value propagation | added `test_module_entry_point_propagates_main_return_value` (no-args → `main()` returns 0 through `raise SystemExit(main())`) |
| 3 | version tests asserted `__version__ in output`, looser than the fixed `skillflow 0.1.0` contract | both tests now assert `f"skillflow {__version__}"` (keeps bump-safety, pins the prefix) |

| 6 | `-> int` annotation unqualified for the `--version` / `--help` exit paths | added a docstring clause noting argparse exits directly on those actions |

## Known limitations

- The fresh-checkout DoD was verified by copying the tracked working tree to a
  scratch directory, not by `git clone`, because nothing is committed yet
  (commits are out of scope for this Run). The copy used
  `git ls-files -o -c --exclude-standard` minus `.venv/` and `plan.md`, so it
  exercises the same file set a clone would carry.
- `uv sync` requires the package index once to fetch `pytest`/`ruff` and (on a
  machine without CPython 3.11) the interpreter. The installed CLI itself needs
  no network. Noted in the README.
- That the `skillflow` console script lands on `PATH` is verified manually via
  `uv run skillflow`, not asserted in-process (that would test uv's shim).

## Answers to the review's open questions

1. **Global install (`uv tool install`).** Not decided in SF-1 and not needed
   here. Recommendation to settle before SF-3: **root detection derives from the
   invocation CWD, walking up for a marker (`.git/` or an existing
   `.skillflow/`)** — not from the installed package location. That keeps a
   future `uv tool install` compatible without rework. SF-3 owns the final call.
2. **`DB_FILE_NAME = "skillflow.db"`.** Confirmed as the concrete choice. SF-A-2
   §2 leaves the filename an implementation detail; `.skillflow/skillflow.db` is
   the value SF-3 should consume. No competing name elsewhere.
3. **Artifact placement / commit.** `plan.md`, `implementation-report.md`, and
   `test-report.md` at the repo root are the **interim protocol until artifact
   storage lands (SF-11 / `.skillflow/artifacts/` per SF-A-2 §5)**. They are the
   durable record of this Run and are **meant to be committed** with the SF-1
   change, so intentionally not gitignored. Finding 4 (ruff `*.md` exclude)
   removes the formatter's authority over them regardless.
4. **Bare `skillflow` exiting 0.** Provisional. It reads better against
   "executable starts" today; once SF-19 adds real subcommands the conventional
   choice is exit 2 for a missing subcommand, and
   [tests/test_cli.py](tests/test_cli.py) `test_no_args_returns_zero_and_prints_usage`
   updates with it. Not a stable contract.
5. **`CLAUDE.md`.** Agreed it should be its own issue rather than drifting;
   out of scope for SF-1. Propose filing it before the next implementation Run
   in this repo.
